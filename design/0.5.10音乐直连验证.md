# 0.5.10 音乐直连

## 原因与处理

- 当前运行环境的 `HTTP_PROXY`、`HTTPS_PROXY` 和 Windows 用户代理均指向 `127.0.0.1:6789`。QQ Music SDK 0.7.3 的 AsyncSession 默认 `trust_env=True`，会继承代理。
- 音乐专用 Client 改为 `proxies={}`、`_session.trust_env=False`；同一 Session 覆盖搜索、歌单、播放地址、登录 HTTP、QIMEI 与设备初始化。
- 音频后端使用 FFmpeg。Windows 构建保存独立的 C 运行时环境副本；实测在播放后修改 Python 环境不能改变路由。因此在 Qt 导入之前加入音乐域名的进程内 `no_proxy` 规则。
- QQ 返回的 CDN 列表中原先首先选择裸 IP，现优先选用绕过规则覆盖的音乐域名节点；当前真实列表提供 `sjy6.stream.qqmusic.qq.com` 等节点。没有覆盖的节点会报错提示重试，避免悄悄恢复代理播放。
- 保留已有 `no_proxy` 内容及代理 URL；不写 Windows 注册表、不修改用户环境变量，LLM/天气的 Qt 网络代码不变。仍使用流式播放，无整首下载等待。

## 验证

- `test_music_proxy.py`：两个本地 HTTP 服务器分别记录源站与模拟代理访问；修改前真实 FFmpeg 播放经过代理，修改后在新进程中播放、设置位置直接访问源站；SDK 在未给源站设置绕过条目的情况下也直连。
- 同一测试检查音乐 MQTT 客户端的代理选择为 None、原代理 URL 和绕过条目保留、CDN 选择跳过裸 IP。
- `test_music_state.py`：列表、歌曲、音量、位置恢复与续播通过。
- 其余 21 项现有回归脚本通过。
- 使用当前保存歌曲与本地凭据读取真实播放地址，再以显式直连请求 512 字节音频：服务器 `sjy6.stream.qqmusic.qq.com` 返回 HTTP 206、`audio/mpeg`、512 字节。
- 没有操作真实扫码确认流程，也没有播放整首真实歌曲；完整播放/定位路由由本地测试音频验证。
