# 0.5.9 后续优化评估

阶段：研究；当前封版回退基准已改为 0.5.10，0.5.9 保留为历史归档。下列 0.5.9 测量仍为原版本的历史结果；音乐直连验证另见 `0.5.10音乐直连验证.md`。

进度：候选 1、4、5 已在 0.5.11 实现，见 `0.5.11优化验证.md`；2、3、6 保留为后续候选。

## 当前证据

- 当前运行的主进程在一次 10 秒采样中占用约 124.8 MB 工作集，累计 CPU 时间增加约 0.047 秒；打包启动器约 8.8 MB。该采样反映当前空闲状态，不代表音乐播放或高频操作时的占用。
- 真实图标的绘制卡顿已通过位图缓存解决。0.5.9 的 52 项分框复测：首次列表绘制约 11 毫秒，后续约 6–7 毫秒，包含并行运行回归脚本时的负载。
- `isac_ui.py` 的 `moveEvent`、`resizeEvent` 每次调用 `store.save()`；分框已经采用延迟保存。
- `Controller` 启动时会创建模型配置、ISAC、控制台和全部状态卡；控制台同时创建三个功能页，音乐页同时初始化播放器和音频输出。
- LLM、天气及模型列表请求在应用代码中未显式设置请求超时。
- 音乐回调只携带请求种类和结果。模拟先选择 A 再选择 B，并按 B、A 顺序返回地址，最终播放源为 A，界面中的当前歌曲仍为 B。模拟使用假的网络桥和播放器，未调用音乐服务，也未修改个人配置。
- 桌面底板透明度及部分视觉参数写在源码中；当前没有运行时主题调节入口。
- LLM 对话在请求完成后显示完整答复，历史仅保留在内存中。

## 候选优化

| 优先级 | 方向 | 用户收益 | 范围与验证 |
| --- | --- | --- | --- |
| 1 | 统一拖动与缩放保存 | ISAC 拖动和缩放也保持顺畅 | 几何和显示偏好合并保存；图标操作使用即时落盘。统计拖动时的写入次数，检查退出后位置恢复。 |
| 2 | 音乐请求一致性与超时反馈 | 连续切歌、搜索和换页时结果对应最后一次操作；网络异常有清晰结束状态 | 为请求增加操作标识，过期回调退出；区分播放地址、搜索、歌单、登录请求。验证乱序回调、失败、取消及续播。超时和重试策略按功能确定。 |
| 3 | 启动按需初始化 | 更快出现桌面分框，降低未使用模块的初始化开销 | 先测启动各阶段耗时，再延迟创建设置界面及未打开的功能页；音乐状态恢复和日程提醒继续可用。收益需要新基准验证。 |
| 4 | 可调的 HUD 参数 | 换壁纸或显示器时也能调到舒适的效果 | 透明度、字号和图标尺寸预览，统一主题参数，提供恢复默认值。用亮暗壁纸及不同缩放验证可读性。 |
| 5 | 跨分框快速查找 | 图标多时减少逐个寻找 | 可配置的快捷入口，按名称筛选现有项目并定位所属分框；搜索结果使用原路径。 |
| 6 | LLM 流式反馈与本地历史 | 减少等候感，重启后继续查看对话 | 分 API 模式处理流式事件、取消及工具执行；工具动作提供明确结果。加入可清理的本地记录和上下文长度管理。兼容性需单独验证。 |

## 建议推进顺序

候选 1、4、5 已按用户选择完成。余下候选中，音乐请求一致性仍有明确代码证据；启动优化需补充分阶段基准，流式对话和历史需单独评估 API 兼容性。

大规模框架重写和持续背景动画暂列后续备选；当前证据更支持先改善已有交互与请求一致性。
