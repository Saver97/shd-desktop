# 0.5.13 分框层级修复

## 现象与原因

两个展开分框重叠时，点击或拖动后创建的那个分框，仍会被先创建的分框遮挡。原实现的 `restack_panels()` 先对折叠分框调用 `lower()`，再对展开分框调用 `raise_()`；Windows 上 `Qt.WindowStaysOnBottomHint` 分框的 `raise_()` 没有改变其原生窗口次序。现场隔离复现中，两个分框的 Win32 z 序在选中与拖动后均未改变。

## 调整

- 分框记录本次运行中的活动分框；标题、图标列表、空白区域和缩放手柄的鼠标交互会更新活动分框。
- 统一按展开、折叠两组排序，活动分框在所属组前。使用已在 Windows 原生测试中确认有效的 `lower()` 从前到后重排整组分框，维持展开高于折叠、分框高于桌面背景、低于普通应用窗口。
- 展开/折叠、拖动完成、缩放完成、场景切换、桌面刷新及快速查找定位走同一排序逻辑。没有更改分框位置、文件、图标隐藏或场景数据结构。

## 检查

`test_panel_z.py` 在 Windows 原生窗口中检查：新展开分框置前、点击标题或图标区置前、后续重复排序保持活动分框，以及展开分框高于折叠分框；同时保留已有的拖动吸附、缩放吸附和布局延迟写入验证。

隔离 Win32 窗口列表检查：展开分框 z 序 247、折叠分框 248、Explorer 桌面背景 249（数字越小越靠前）。这些序号仅用于本次相对次序验证，不代表固定系统层级值。
